# Customer erasure and re-import suppression

Customer redaction now deletes matching stored orders and cascades their line items, refunds and transactions. It closes linked privacy exports, removes order-linked leak records, invalidates profit snapshots and creates a durable recalculation job. The worker's delivery recovery picks up that job; no Redis connection is needed to commit the erasure itself. Totals change because erased orders are no longer included.

Tenant-scoped HMAC markers suppress later imports by erased order ID or customer ID. Markers contain keyed hashes, not the original IDs. Order persistence and customer erasure lock the same store row, so overlapping workers cannot restore an order between the marker check and insertion. Forced imports also respect suppression. Deleting the store cascades its markers.

Apply `20260924180000_erasure_markers` before starting the updated application. Keep ENCRYPTION_KEY stable: it currently also keys suppression hashes. Rotating it without a suppression-key migration would invalidate matching; a versioned key-rotation procedure remains required before production. Test/development fallback keys must never be used in production. Hash markers are a restricted-purpose retention measure, not a claim of anonymization.

Regression checks include tenant isolation, forced/customer-less replay, new order IDs for erased customers, concurrent ingestion/erasure, repeated erasure and order-only erasure preserving unrelated orders. PostgreSQL CI runs the migration and these scenarios against synthetic data.

Still unresolved: backup and log retention, customer details manually entered in AI prompts, derived briefing retention, externally downloaded exports, no-store privacy workflows, and suppression across uninstall/reinstall after full store erasure. No production deployment or compliance certification is implied. The earlier privacy-request checkpoint's retained-order limitation is superseded for new customer-erasure events; previously processed erasures require a reviewed remediation plan because their original identifiers were cleared.

Reference: [Shopify mandatory privacy webhooks](https://shopify.dev/docs/apps/build/compliance/privacy-law-compliance).
