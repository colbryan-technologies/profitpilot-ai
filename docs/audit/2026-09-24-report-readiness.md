# Report readiness checkpoint

Overview no longer considers a single snapshot sufficient for a multi-day report. It hides financial metrics and alert summaries while required daily snapshots are absent, initial historical sync has not completed, latest order synchronization is missing/over 24 hours old, relevant jobs remain queued/running, recent failures remain unresolved by recalculation, or snapshots use an old calculation version. Today's snapshot must also be recent, using the store-local date. Product reports reject an unready period with an actionable Data health link.

Ask and weekly digest generation require ready current-period data before preparing explanations. Comparisons with an unready previous period are unavailable rather than treated as zero. Stale/error/disconnected remote advertising accounts add an explicit warning; manual spend is excluded from this automatic-sync check. These thresholds are conservative product defaults, not guarantees of source freshness.

Scope and limits: exact historical import ranges and source-order reconciliation are not yet recorded. A completed sync is not proof of full Shopify coverage. Missing zero-activity days now block a report instead of being silently assumed zero; recalculation currently starts at the earliest stored order or expense, so explicit imported coverage is needed to safely create earlier zero-day snapshots. Existing order-detail/list screens still show individual stored calculations with their current caveats, and saved briefing display is not revalidated against later source changes. Live worker/webhook races and ad spend paused by plan downgrade need further acceptance work. This checkpoint is not a production-readiness signoff.

Tests cover complete versus partial date sets, absent historical sync, stale order sync, pending recalculation, calculation versions, store-local current-day freshness, advertising warnings and PostgreSQL readiness transitions. No schema migration, production deployment or App Store submission occurred.
