# Privacy request workflow checkpoint

## Implemented

- Verified customer data-request webhooks create a tenant-scoped pending request instead of only an audit entry. Preserve only resource identifiers, receipt time and a 30-day due date; discard contact details. Duplicate deliveries cannot extend deadlines or reopen fulfilled requests.
- Merchants can see pending/overdue requests in Privacy requests and download a private, streamed JSON Lines export. Each page is scoped to the authenticated store and a still-pending request. It includes stored orders matching the customer or requested order IDs, with their recorded line items, refunds and transactions. No match yields an empty export, never the whole store.
- Downloads carry no-store/private and attachment headers. A final completion record distinguishes a complete export from an interrupted file. Downloading does not automatically record fulfillment.
- Merchants explicitly confirm completed delivery through their support process. Fulfillment records an audit event and clears customer/order lookup identifiers from the request. Customer redaction closes matching pending exports; store deletion cascades all requests.
- Repeated shop deletion scrubs orphan webhook payloads and sessions even after the store row has disappeared.

## Operation and acceptance

Apply migration `20260924170000_privacy_requests` before starting the updated web process and worker. The worker creates requests, and the authenticated Privacy requests screen provides exports. Review internal financial fields before forwarding any export to a customer. Do not treat an interrupted download or a file without the final `complete: true` record as complete.

Unit checks cover webhook payload minimization, export authentication, paging, cache headers and interrupted downloads. PostgreSQL integration checks cover deadline preservation, deduplication, cross-tenant denial, identifier clearing, redaction and orphan cleanup. CI runs these against synthetic records in an isolated database.

## Still required before launch

This workflow does not send email, automatically verify support delivery, or certify privacy compliance. Merchant delivery, monitoring of overdue requests, uninstalled-store/no-store request handling, identity verification and secure disposal of downloaded files require an operational process and live acceptance testing.

Customer redaction currently removes customer lookup fields while retaining linked financial order records. Suppression of later re-import, treatment of those retained records, backup retention, log retention, and any customer details entered in merchant AI prompts need further implementation/review. These remain explicit release blockers; do not describe current retained records as fully anonymous or launch this build as privacy-complete.
