# Import coverage checkpoint

Historical order imports now filter by processed_at, matching profit dates, with fixed inclusive start/exclusive end timestamps stored as versioned importWindow metadata on the existing SyncJob. Incremental updated_at scans also retain a fixed window across retries. The five-minute overlap remains. Successful historical ranges establish coverage; overlapping successful incremental ranges can extend them. Failed, cancelled, corrupt and legacy records do not establish coverage. No migration or invented backfill is used.

Historical imports require recorded read_all_orders permission to avoid assuming processed-date completeness from Shopify's limited creation-date access. This check relies on saved installation scopes; live granted-scope and API acceptance still require validation. Legacy jobs already holding an unversioned cursor fail with a resync instruction instead of reusing it under a different query. Data health has a Reimport history action and recorded coverage display.

Recalculation is queued after the import is marked complete, including empty incremental runs. It adds covered empty dates to the snapshot rebuild. Readiness now also requires coverage for every selected date. Partial first days are conservatively excluded; partial last past days are excluded; the ongoing day is allowed only through the recorded import timestamp and labelled provisional. Failed/cancelled windows cannot create apparently zero-profit dates. Existing older snapshots remain stored, but cannot alone establish source coverage.

Limitations: a completed traversal is not a transactional Shopify snapshot or reconciliation of source totals. Concurrent Shopify updates, deleted orders, approvals and live scope behavior still need acceptance tests. Recorded incremental overlap cannot replace missing historical baseline. Resync on a legacy running job may require its failure/cancellation to finish before the replacement is accepted. Coverage scans currently read completed import metadata; indexing/compaction should be assessed at scale. No production deployment or App Store submission occurred.

The unchanged orders GraphQL operation passed toolkit schema validation for 2025-10. Search filter names were checked against the official [orders documentation](https://shopify.dev/docs/api/admin-graphql/2025-10/queries/orders). Tests cover missing/legacy metadata, gap-preserving extension, adjacent historical ranges, timezone boundaries, failed/cancelled imports and zero-order recalculation.
