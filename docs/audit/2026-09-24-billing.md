# Billing verification and Ask allowance checkpoint

Ask now resolves the tenant's plan through the billing service before reserving usage. Configured billing rejects missing shop identity, incomplete API responses and unmapped/ambiguous plan handles. A missing remote subscription removes paid access; API errors do not silently reuse stale paid access. A fresh mirror lasts at most five minutes, and an ended billing period forces revalidation. An explicit remote null continues to receive the existing free allowance.

A short PostgreSQL transaction locks the tenant row, counts Ask attempts in the rolling 24-hour window and creates a reservation before grounding or provider work. Concurrent requests cannot spend the same remaining slot. Completion updates the reservation rather than inserting another usage record. Fallback, interrupted and failed attempts count, avoiding unlimited retries after a process crash; the Ask screen states this policy. Provider calls run outside the database lock. No schema migration is required.

Validation includes rejected/malformed billing responses, cancellation/downgrade, expired cache, and a real PostgreSQL concurrent reservation test. The unchanged Partner query was validated against the configured unstable schema with the Shopify AI Toolkit. [Shopify activeSubscription documentation](https://shopify.dev/docs/api/partner/2026-07/active-subscription) describes the contract and explicit null for no contract.

This is partial billing enforcement. Order/history limits, advertising account allowances, digest and export feature gates, live pricing transitions, and failed-attempt allowance policy review remain before paid onboarding. Privacy exports must remain available independently of paid features. No charges are created and nothing is deployed. The five-minute mirror permits a bounded delay after cancellation; webhook invalidation shortens it when received. In-flight work can complete under its already-reserved allowance.
